## Milestone plan

### M0 — Foundation

1. Commit baseline: PRD (done — `docs/PRD.md`), decision docs, `docs/agents/*`; resolve dangling `CLAUDE.md` deletion
2. Restructure to `src/`: `src/app`, `src/features/{auth,listings,admin,uploads}`, `src/lib`, `src/config`, `tests/`; rename package to `coaching-ngj`
3. `src/lib/env.ts` — Zod-validated env at boot; `.env.example`
4. `docker-compose.yml` (local Postgres); CI scaffold (Biome lint, typecheck, build)
5. Decision docs (done — 0001, 0002)

**DoD:** build + lint + typecheck green; decision docs written.

### M1 — Data layer

1. Read current Prisma + Better Auth docs; init Prisma with `postgresql`
2. Schema per PRD §7; Better Auth tables via `@better-auth/cli generate` (not hand-written)
3. `prisma migrate dev`; `prisma/seed.ts` — 7 areas + 8 categories (bn+en) + admin user (**confirm exact area list — open Q2**)
4. `src/lib/db.ts` Prisma singleton; Vitest wired

**DoD:** clean `migrate dev` + seed on a fresh DB; schema reviewed.

### M2 — Auth

1. Better Auth: email/password, email verification, reset, Google OAuth; `/api/auth/[...all]`
2. Pages: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`
3. Provision Gmail SMTP (App Password) + Turnstile account → env vars; Turnstile on register/reset
4. DB-backed rate limiter (`src/lib/rate-limit.ts`) on login/register/reset
5. Server-side guards: `requireUser()`, `requireOwnerOf()`, `requireAdmin()`
6. E2E: register→verify→login→logout; unit tests for limiter

**DoD:** E2E journey green; wrong-password ×6 → rate-limited; tokens single-use + expiring.

### M3 — Owner listings (no images)

1. `features/listings/`: shared Zod schema (form + server, server is source of truth), `service.ts` (**only** status writer), `policies.ts`
2. Dashboard: list with status badges + rejection reason; create/edit (React Hook Form + Zod), archive, submit
3. Slug: `slugify(name) || "coaching"` + `-` + 6 random chars, generated once, immutable
4. `ListingAuditLog` row on every status transition
5. Tests: transition matrix, ownership (404-not-403), E2E owner journey

**DoD:** owner cannot touch others' listings (tested); cross-owner id → 404.

### M4 — Images (R2)

1. Provision R2 bucket + public image domain; CORS (app origin, PUT only)
2. `POST /api/uploads/presign`: session + ownership + limits → `{ uploadUrl, key }`, key `coachings/{coachingId}/{random}.webp`, ~5 min expiry
3. Client uploader: compress to ≤1600 px / WebP (`browser-image-compression` — **approval gate**) → PUT → record keys
4. `HeadObject` verification of every key on save (prefix, size, content type); delete objects with images/listings
5. `next/image` `remotePatterns` locked to image host; abuse-case tests (unauthed, not-owner, over-limit, bad type)

**DoD:** upload/replace/delete works; abuse cases rejected and tested.

### M5 — Public pages

1. `/` (search box, area chips, latest), `/coachings` (nuqs filters in URL, 12/page, `publishedAt desc, id desc`), `/coachings/[slug]`, `/areas/[slug]`
2. Server Components everywhere except forms/uploader/gallery; `select` only card fields + cover
3. Empty state with "clear filters", error/loading states
4. Bengali-capable font for user content; `whitespace-pre-line` plain-text details; `tel:` + `wa.me` buttons

**DoD:** LCP < 2.5 s, CLS < 0.1, INP < 200 ms on mid-range mobile profile.

### M6 — Admin moderation

1. `/admin/listings?status=PENDING` queue; approve / reject(reason) / unpublish — via `service.ts` only
2. Minimal area/category management for admins
3. E2E: only `PUBLISHED` publicly visible; every transition writes an audit row

**DoD:** no unreviewed listing ever publicly visible (tested).

### M7 — SEO + a11y (no i18n/hreflang — English-only)

1. Metadata + canonical URLs per page; `sitemap.xml` (published listings + area pages); `robots.txt` (disallow `/dashboard`, `/admin`, `/api`)
2. JSON-LD `EducationalOrganization`/`LocalBusiness`; OG image = cover; semantic HTML, one `h1` per page
3. A11y pass: labels, visible focus, `aria-live` errors, AA contrast, `alt` text

**DoD:** Rich Results test + PageSpeed checks pass.

### M8 — Hardening + launch

1. Security review vs §10: security headers (CSP, HSTS…), env validation, no `any`, no secrets, no password/token logging
2. Sentry (client + server); `/api/health` (DB ping); structured logging
3. Backups + **tested** restore; `docs/runbook.md`; deploy + rollback plan

**DoD:** production checklist (PRD §13) fully ticked.

## Operating rules (from PRD §14 — binding)

1. One milestone at a time; stop and summarize at each DoD.
2. Short plan before coding a milestone; approval required for new dependencies or architectural choices.
3. Never trust the client: Zod validation + `requireUser/requireOwnerOf/requireAdmin` on every mutation.
4. No business logic in components or route files; `features/*` import each other only via exported `index.ts`.
5. No `any`; no secrets in code/logs/client bundles.
6. Every schema change = a Prisma migration.
7. Tests for policies, status transitions, validation, and the critical E2E journey.
8. Docs win over memory; read `node_modules/next/dist/docs/` before using Next.js APIs.
